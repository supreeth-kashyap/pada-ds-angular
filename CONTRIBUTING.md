# Contributing to Pada for Angular

Thanks for helping out. A few ground rules keep `main` releasable:

- **Open an issue first** for anything bigger than a small fix, so we can agree on the approach
  before you write code.
- **Work on a fork or a branch and open a pull request.** `main` is protected: changes land only
  through pull requests, squash-merged, after CI passes.
- **Run the checks locally** before you push: `npm run check`.
- **Keep pull requests focused.** One change per PR, with a description of what it does and why.
- **Security issues** go through the private channel in [SECURITY.md](SECURITY.md), never a public
  issue.

How to build a component, step by step, is in [docs/contributing.md](docs/contributing.md).
